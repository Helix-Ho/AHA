# AHA 공통 개발 기록

필요한 결정의 이유를 찾아 읽는 기록이다. 현재 계약은 [계약 문서](contract.md), 작성 기준은 [History 정책](../README.md#history-기록-기준)을 따른다. 기록 날짜는 기록일이며, 이전 개발을 정리한 항목은 실제 결정일과 다를 수 있다.

## 2026-10-11 · 취득 원본과 공개 회귀 입력의 분리

실제 VWorld·토지이음 응답은 재배포 조건이 자료별로 달라 공개 검사 입력에서 제외했다. 원본과 축약 재현은 해시·출처를 포함해 로컬 `.local/test-data/`에 보존하고, 공개 검사는 독립 합성 입력으로 동일한 제품 경로의 주요 실패 조건을 판정한다. 원본 범위는 명시적으로 선택할 때만 실행하며 자료가 없거나 변형되면 통과 대신 실행 불가로 처리한다. 현재 실행 방법과 보호 범위는 [검사 안내](build-and-test.md#회귀-검사-실행)에 둔다.

## 2026-10-10 · 준비 결과의 소유권을 패널·서버 수명에서 분리

Topo의 계산과 모델 반영을 한 호출로 묶으면 사용자가 다른 편집을 진행하거나 결과의 생성 시점을 선택하기 어려웠다. 문서당 준비 작업 하나를 공통 Jobs가 소유하고, 패널과 MCP가 같은 핸들로 연산·생성·폐기를 요청하도록 바꿨다. 문서 변경 잠금은 생성에만 사용하며 패널 닫힘과 MCP 중지가 준비 결과를 버리지 않게 했다.

시간 제한과 사용자 취소를 같은 안내로 표시하면 내부 연산 지연을 사용자의 폐기로 오해하게 된다. 종료 원인을 공통 작업에서 보존하고 패널은 그 사유를 표시한다. Topo 준비는 계산량에 따라 길어질 수 있으므로 자동 기한을 제거하고 수동 취소·대상 종료를 유지했다. 일반 조회 기한과 개별 통신 제한은 별도로 유지한다. 늦게 반환된 형상은 폐기하며, 작업 시간 경계에 주입한 시계와 지연 응답으로 구분을 검증한다.

준비 형상은 종료 JSON 기록과 달리 시간으로 만료시키지 않는다. 생성에 들어간 작업의 취소와 중복 요청은 객체를 반쯤 남기거나 두 번 추가할 수 있어, 반영·복구가 끝날 때까지 원자적인 상태로 관리한다. busy 상태는 준비 결과를 보존해 재시도하고 실제 문서 무효화는 해제한다. 계약은 [긴 작업](contract.md#긴-작업), 재현은 [작업 검사](../../src/aha/checks/core/JobChecks.cs)와 [호스트 HTTP 검사](../../src/aha/checks/native/RuntimeWireChecks.cs)에 있다.

## 2026-10-05, 2026-10-07 · MCP 설정과 독립 기능의 선택 기준

RhinoAI의 실제 호출에서 AHA의 주소·필지 조회와 Info 저장은 사용됐지만 EumCrawl은 선택되지 않았다. 미호출만으로 AI의 선택 이유를 확정할 수는 없으므로 호출을 강제하지 않고, 규제 후보와 원문 열람의 용도를 도구 설명에 드러냈다. 평면 정보·주변 모델·원문·수치 후보는 호출자가 목적에 맞게 선택하도록 구분했다.

Topo의 상세 설정도 설명 문장만으로는 기본값·범위를 찾기 어려워 공개 스키마와 실제 검증을 맞췄다. 새로운 모델 추가를 기존 객체 삭제와 같은 파괴적 작업으로 표시하지 않도록 annotations를 나눴다. 현재 설명·스키마는 [MCP 안내](mcp.md), 재현은 [설치본 호출 검사](../../src/aha/checks/native/RuntimeWireChecks.cs)에 있다.

AHA 결과를 다른 모델링 기능에서 활용하는 조합을 막지 않도록 초기화의 포괄적인 대체 스크립트 금지 문구도 제거했다. 별도 AHA 프로토콜이나 강제 호출 순서를 만드는 대신 공개 기능의 실행·검증을 책임지고 외부 AI의 설계 판단은 맡지 않기로 했다.

## 2026-10-05 · 검사 실행의 소유권과 패키지 내용 검증

검사 결과는 현재 실행에서 나온 판정이어야 한다. 실행기 점검에서 이전 성공 보고서가 남는 경로와 Rhino 스크립트 재실행으로 중복 작업이 시작되는 경로를 발견했다. 등록 검증을 공유하고 실행별 보고서와 프로세스 단위 잠금을 두었다. 관찰 시간 초과는 진행 중인 Rhino 작업의 취소와 다르므로, 실제 종료를 확인하기 전에는 다음 실행을 허용하지 않는다. 재현 입력은 [실행기 검사](../../src/aha/checks/runner/test_runner.py)에 남겼다.

패키지 검사도 금지 확장자 몇 개를 찾는 방식만으로는 개발 문서 혼입을 발견하지 못했다. 허용할 제품 파일 집합과 현재 빌드의 동일성을 확인하는 방식으로 바꿨다. 재현과 판정은 [패키지 계약 검사](../../src/aha/checks/package/test_package.py), 현재 절차는 [빌드·검사 안내](build-and-test.md)에 있다.

## 2026-10-05 · MCP 입력 거절과 정정 가능한 객체의 발견

중복 JSON 키를 가진 실제 MCP 요청이 명시적인 오류 대신 빈 HTTP 200으로 끝났다. `JsonNode`가 객체 사전을 늦게 구성하면서 발생한 예외가 기존 오류 처리 경계 밖으로 나간 것이 원인이었다. 예외 종류를 넓게 덮는 대신 HTTP 입력 전체에서 중복 키를 먼저 검사하고, 중첩 객체·배열도 도구 실행 전에 거절하도록 했다. [HTTP 회귀 검사](../../src/aha/checks/core/Program.cs)에 응답 내용과 미실행을 함께 확인하는 재현 입력을 남겼다.

별도로 대지 목록 필터가 저장용 Info 검증을 사용해 잘못된 층수 값이 있는 대지를 숨기는 문제를 찾았다. 외부 편집 값을 읽고 고칠 수 있다는 Info의 책임에 맞춰 탐색은 읽기 규칙을 사용하고 저장에서 엄격한 검증을 유지했다. [설치본 HTTP 검사](../../src/aha/checks/native/RuntimeWireChecks.cs)는 잘못된 값이 있는 대지를 찾아 읽고 정정하는 흐름을 재현한다.

## 2026-10-05 · 문서의 책임과 선택적 기록을 소스에 맞춤

처음 정리한 History는 테스트·시나리오의 완료 장부에 가까웠다. 다음 개발자가 필요한 판단과 이유를 되짚을 수 있도록 중앙 기록 폴더를 없애고 각 소유자의 HISTORY로 바꿨다. `src`, `dev`, `docs`도 `aha`와 각 도구의 같은 책임 단위로 대응시켜 변경할 문서 범위를 명확히 했다.

개발 진입점에는 익숙한 README 이름을 유지하고, 과거 판단과 외부 자료는 필요한 문제를 조사할 때 찾아 읽도록 구분했다. OpenAI 문서의 중요도·근거·중복 방지 기준을 참고했지만 파일 구조는 AHA의 필요에 맞춰 정했다. 현재 기준은 [문서 관리 정책](../README.md#문서-관리), 참고 범위는 [OpenAI 자료 안내](../references/OpenAI/README.md)에 있다.

## 2026-10-05 · 모델링 호스트와 AI 실행자의 책임을 분리

독립 웹 편집기·Grasshopper 애드온·Rhino 플러그인을 비교한 뒤 Rhino의 기존 모델링과 편집 기능을 활용하는 플러그인에 집중했다. 도구 조합으로 건축 설계 과정을 확장한다는 방향은 유지하되, 현재 도구를 만들기 위해 오케스트레이션 에이전트까지 먼저 만들지는 않기로 했다.

RhinoAI 조사 이후에도 AHA는 자체 사용 가능한 도구와 명시적인 MCP 기능을 제공하고 AI 대화·모델 선택·로그인은 외부 클라이언트가 맡도록 했다. 특정 AI 제품이 개선될 때 업무·형상 계산까지 바꾸지 않기 위한 구분이다. [RhinoAI 참고 범위](../references/RhinoAI/README.md)는 런타임 의존성이나 실사용 연동 완료를 뜻하지 않으며, 일반 MCP 검사만으로 특정 클라이언트의 실제 활용까지 입증할 수는 없다.

## 2026-10-05 · 등록 패널 한 경로와 동일한 설치 패키지

별도 창과 Rhino 등록 패널이 함께 남으면 같은 도구가 다른 방식으로 열려 혼란을 만들었다. 등록 패널 경로로 통일하고 배치·도킹은 Rhino가 관리하도록 정리했다. 다른 패널의 배치에 영향을 줄 수 있는 강제 플로팅 조작도 넣지 않았다. 근거: [패널 등록](../../src/aha/rhino/Plugin.cs), [패널 연결](../../src/aha/rhino/ToolPanels.cs).

개발 폴더에서는 되지만 다시 설치하면 달라지는 상태를 피하려고 개발·배포 패키지를 분리하지 않았다. 같은 버전 문자열이 오래된 로드를 숨길 수 있어 [빌드 식별 검사](../../src/aha/checks/native/BuildIdentity.cs)는 실제 모듈을 대조한다. 제품·Info 형식·MCP 규약의 버전도 서로 다른 변경을 나타내므로 구분했다. 현재 패키징·버전 기준은 [빌드·검사 안내](build-and-test.md)에 있다.

## 2026-10-05 · 활성 문서보다 실행 대상과 작업 수명을 기준으로 함

사용자와 MCP가 문서를 전환하며 사용할 수 있어 호출 순간의 활성 문서를 계속 따라가면 다른 문서를 변경할 위험이 있었다. 실행 대상 문서와 객체를 고정하고 같은 문서의 중복 변경을 막도록 공통 책임을 정했다. 서버를 패널별로 두지 않고 문서 ID로 대상을 구분한 것도 같은 실행 경계를 유지하기 위한 선택이었다. 현재 문서·서버 수명은 [공통 구조](architecture.md#문서와-작업의-수명)를 따른다.

작업 시작·취소 요청·문서 반영 완료를 구분해야 실제 결과와 상태가 어긋나지 않는다. 점검 과정에서 작업 수 제한의 확인과 등록이 분리되어 동시 요청이 한도를 넘는 원인을 찾아 하나의 임계영역으로 고쳤다. 근거: [문서 접근](../../src/aha/rhino/DocumentAccess.cs), [작업 회귀 검사](../../src/aha/checks/core/JobChecks.cs), [서버 수명 검사](../../src/aha/checks/lifecycle/Program.cs).

## 2026-10-05 · 시나리오 장부 대신 재현 가능한 핵심 검사를 남김

초기 개발 점검에서는 실제 사용과 MCP 시나리오로 결함을 찾았다. 이 절차는 실제 KEY·AI·준비된 사용자 객체에 묶여 그대로 반복하기 어려웠다. 도구별 계약과 발견한 오류 원인을 고정 입력으로 재현하고 자동 판정하는 검사로 정리했다.

계산 검사와 실제 Rhino 호스트 검사는 구분하되 등록·결과 집계를 공유한다. HTTP·시간·저장소·응답 완료 시점만 제어해 실패를 재현하고 제품의 전역 시험 모드는 만들지 않았다. 공통 실행기가 성공을 선언하기 전에 모든 비동기 검사가 끝나야 하는 이유도 이 과정에서 명확히 했다. 근거: [검사 책임과 실행기](../../src/aha/checks/README.md).

Topo 서비스 검사에서 기존 객체·정보·레이어는 그대로인데 활성 문서의 `Modified`만 바뀌는 현상을 발견했다. AHA 없이 Rhino 8의 headless Undo만 실행해도 재현되어, 수정 표시를 문서 내용 보존과 구분하고 제품에서 강제로 복원하지 않았다. 내용 보존은 ID뿐 아니라 기하 CRC·속성·선택·레이어 상태로 확인하도록 강화했다. 이 호스트 한계를 실제 내용 변경을 허용하는 이유로 확대하지 않았다. 재현은 [공통 문서 보존 검사](../../src/aha/checks/native/RuntimeNativeChecks.cs)와 [Topo 서비스 검사](../../src/topo/checks/service/TopoServiceChecks.cs)에 있다.
