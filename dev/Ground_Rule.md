# Ground Rule

AHA의 도구를 만들고 확장할 때 적용하는 개발 대원칙이다.

1. **재사용 가능한 도구를 개발하고, 조합으로 전체를 만든다.** 한 번에 전체를 구현하지 않고 책임이 분명한 도구 또는 그 일부를 완성하며 확장한다.
2. **모듈의 경계에는 이유가 있어야 한다.** 기존 도구의 재사용과 더 작은 모듈로의 분해를 검토한다. 책임·재사용 가능성·변경 이유·복잡성을 근거로 나누거나 묶는다.
3. **역할과 구현 방법을 구분한다.** 같은 역할을 API·파일·규칙·AI 등 여러 방법으로 구현할 수 있다. 방식별로 다른 부분과 공유할 처리 부분을 구분한다.
4. **연결을 명확히 하고, 도구를 독립적으로 발전시킨다.** 입력·출력·변경과 실패의 의미·의존 관계를 계약으로 정한다. 같은 역할의 대체 도구는 같은 연결 규약을 지키고, 다른 도구의 내부 구현에 직접 의존하지 않는다. 핵심 기능은 UI와 분리한다. 사람의 직접 사용과 MCP 등 외부 호출은 같은 실행 기능과 업무 검증 규칙을 사용하며, 특정 AI 클라이언트에 종속시키지 않는다.
5. **구현과 문서를 같은 책임 단위로 관리한다.** 소스·개발 문서·사용자 문서의 소유권을 맞춘다. 계약의 원본은 그 책임을 가진 곳에서 관리하며, 변경 시 연결된 도구·검사·문서의 영향을 함께 확인한다. 현재 계약과 설계, 과거 판단을 구분한다.

문서의 작성·갱신은 [문서 관리 정책](README.md#문서-관리)과 [History 기록 기준](README.md#history-기록-기준)을 따른다.
