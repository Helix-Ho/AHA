## 2026-10-12 · 지형 계산 범위와 작업별 재사용

지형 셀마다 전체 출력 영역을 검색해 평지에서도 셀 수와 영역 수의 곱만큼 조회했다. 기존 셀별 목록을 한 번 채워 삼각분할과 대지경계 투영이 함께 사용하도록 했다. 정확 Near의 출력 셀과 근사 영역의 포함 범위가 다를 수 있으므로 셀 선택은 정확 분할 결과를 유지한다. [지형 검사](../../src/topo/checks/native/FarSurfaceChecks.cs)는 복수 역할·구멍·도로를 가로지르는 투영 경계와 제한된 대지 영역을 보호한다.

작은 Site마다 전체 취득 지형의 평면 그래프를 다시 만들고, 정확 Near의 각 패치마다 전체 도로 색인을 다시 구성하는 비용도 있었다. 원래 셀·높이를 유지한 대지 셀 창과 작업 내 불변 도로 색인을 사용하도록 했다. 도로 솔버는 영향 없는 노드의 해가 정확히 0이므로 영향 영역만 원래 순서로 반복한다. 목적함수·잔차·±3m 제약과 실제 형상 검증은 유지한다.

떨어진 Near의 전체 외곽 상자를 사용하면 사이의 Far 표고까지 등고 범위가 되어 정상 Near를 거절할 수 있었다. 독립 Near마다 복원 여유를 둔 셀 창을 선별한다. 원단면을 곡선 경계까지 먼저 축소하면 후속 작은 상세 판정의 경계가 바뀌므로 창 안의 원단면과 필요한 이웃 세분점은 유지한다. DEM 취득 한도는 64타일로 두되 정상 수집·수렴·정제를 고정 요청·반복·형상 개수만으로 실패시키지 않는다. 원천 완전성과 숫자·좌표 표현 검사는 유지한다. [단면 범위 검사](../../src/topo/checks/core/ContourPrecisionChecks.cs), [도로 해 검사](../../src/topo/checks/core/RoadSolverChecks.cs).

## 2026-10-11 · 설정 입력과 지도 복원의 책임

범위의 값 차이만으로 버튼과 직접 입력을 구분하면 입력값까지 배수로 바뀔 수 있어 두 동작을 분리했다. 지형 요청 한도는 안내뿐 아니라 공통 연산 가능 판정에 연결했다. 작업 잠금 중 지도의 `ready`까지 무시하면 새 HTML의 초기화가 멈추므로 현재 세대의 초기화와 선택·타일 요청을 구분하고, 복귀 때 현재 화면을 갱신한다. 페이지 세대와 타일 요청 순번을 공유하면 이전 타일 메시지가 새 초기화를 거절할 수 있어 분리했다. 모든 메시지를 페이지별로 검증하며, 작업 종료 상태 재적용이 입력 오류를 지우지 않도록 두 안내의 수명을 분리했다. [패널 검사](../../src/topo/checks/service/TopoPanelChecks.cs), [지도 수명 검사](../../src/topo/checks/service/MapNavigationChecks.cs).

## 2026-10-11 · 내장 지도와 브라우저 탐색의 분리

macOS의 WebView Reload는 `LoadHtml`로 넣은 내용을 다시 실행하지 않고 빈 `about:blank`를 열었다. KEY revision이 그대로이면 패널도 HTML을 재로드하지 않아 빈 지도가 지속됐다. 지도는 내장 화면이므로 브라우저 메뉴와 준비된 페이지의 탐색을 막고, KEY 변경에 필요한 호스트 재로드만 허용한다. [실제 WebView 검사](../../src/topo/checks/service/MapNavigationChecks.cs)는 반복 Reload 뒤 선택 보존과 KEY 상태 변경의 재초기화를 확인한다.

## 2026-10-11 · 지붕 띠와 건물 프로파일의 분리

Near 파라펫은 확정된 지붕 영역에서 안쪽 offset을 뺀 뒤 별도 Extrusion으로 만든다. 본체와 합치면 일정 단면을 유지할 수 없고, 접촉 프로파일을 먼저 나누면 분해 이음선에 불필요한 띠가 생길 수 있어 띠 계산을 앞에 둔다. 본체·기초·파라펫은 같은 투영 윤곽을 공유하며 지반·Contour를 다시 계산하지 않는다. [파라펫 검사](../../src/topo/checks/core/ParapetProfileChecks.cs)는 중정·좁은 지붕·분리 영역을 해석적 면적으로 보호한다.

## 2026-10-11 · 상세 생략과 기초 조회의 원본 통일

도로 경계와 정리된 경계를 각각 모델 격자로 반올림한 뒤 차집합하면 실제로 생략하지 않은 가늘고 긴 영역이 생겼다. 이를 상위 판에 누적하고 표본화한 노출면으로 지반을 다시 조회하면서 기초가 과도하게 내려가고 전체 판을 반복 계산했다. 작은 상세의 생략 영역을 offset 중간 정밀도에서 먼저 확정한 뒤 한 번만 모델 격자로 전달하며, 실제 출력과 지반 판정은 같은 유한 경계 영역을 사용하도록 했다. 정밀도나 상세 기준을 완화하지 않고 [반복 정리·기초 회귀](../../src/topo/checks/core/ContourPrecisionChecks.cs)와 불광 고정 입력으로 보호한다.

등고 단면이 새로 자른 경계만 정리하면, 앞서 대지를 제외하면서 생긴 좁은 연결부가 남았다. 역할 분할 직후 대지 절단의 생략을 먼저 확정하고, 도로 내림·기초 하강으로 원단면보다 낮아진 상세판까지 전달한다. 지지판·기단의 피복은 별도로 유지한다. [정밀도 검사](../../src/topo/checks/core/ContourPrecisionChecks.cs)와 [실제 입체 검사](../../src/topo/checks/native/ContourChecks.cs)가 좁은 연결부·상하 지지·보호 경계를 확인한다.

변하지 않는 역할·레벨 입력과 정규화 영역은 작업 안에서 재사용한다. 생략 영역과 노출 높이를 인덱스로 조회하고, 기초 하강은 활성 구멍·누적 생략·노출면에 영향이 있는 판과 건물 묶음으로만 전파한다. 높이만 겹치는 먼 판까지 노출면 의존성에 넣으면 무관한 변경도 재계산을 유발하므로, 정확 영역의 범위가 만나는 후보만 의존 집합에 둔다. 실제 좁은 지반 생략에 따른 정당한 하강과 작은 양의 겹침은 유지한다. 현재 구조는 [Contour 설계](architecture.md#contour-계산과-출력)에 있다.

## 2026-10-10 · 저장 동등성의 의미

Rhino는 재열기 과정에서 레이어 표의 숫자 인덱스를 재배치할 수 있다. 문서 간 저장 검사는 레이어 GUID·부모·표시·객체 정보와 같은 Rhino API의 형상을 비교하며, 인덱스나 서로 다른 reader의 bbox를 동등성 기준으로 쓰지 않는다. [저장 검사](../../src/topo/checks/native/ModelPersistenceChecks.cs)는 번호 재배치와 실제 정보·형상 변경을 구분한다. Undo 기록 번호도 문서별 연속 번호가 아니므로 다른 문서의 작업과 무관하게 실제 한 번의 Undo 효과로 판정한다.

## 2026-10-10 · 형상 준비와 문서 생성의 분리

취득 이후의 형상 계산과 객체 반영을 함께 UI 스레드에서 실행하면 긴 계산 동안 Rhino 편집이 막혔고, 패널 수명에 작업을 묶으면 다른 호출자가 준비한 결과를 이어서 사용할 수 없었다. 문서 기준과 입력을 먼저 복사하고 독립 형상을 백그라운드에서 준비한 뒤 명시적 생성으로 반영하도록 분리했다. 전체 모델과 XY가 같은 준비 소유권·공통 작업 수명을 사용하며, 문서 변경 잠금은 실제 생성 구간에만 둔다. 준비 자원은 패널이나 MCP 연결이 아닌 문서별 작업이 소유한다. [준비 계약](contract.md#준비-수명과-명시적-생성), [준비 형상](../../src/topo/shared/Rhino/PreparedModel.cs), [패널 수명 검사](../../src/topo/checks/service/TopoPanelChecks.cs).

Rhino는 Brep의 준비된 표시 캐시와 달리 Extrusion의 사전 Render Mesh를 객체 등록 시 보존하지 않았다. 이 중복 준비를 제외하고 Extrusion의 화면 표현은 Rhino에 맡겼다. 실제 입체와 AHA가 직접 만든 Mesh의 검증은 유지하며, 표시 문제를 고치기 위해 형상·공유 경계·사용자 표시 설정을 바꾸지 않는다. [형상 책임](contract.md#형상-검증과-화면-표시), [RhinoCommon 확인](../references/RhinoCommon/README.md#준비-형상과-표시망).

## 2026-10-10 · 공유 단면과 원본 경계 연결

매 레벨에 모든 삼각형을 잘라 합집합하던 추출을 공유 변의 교점과 활성 삼각형 순회로 교체했다. 이웃 셀의 세분 수가 다르면 공유 변부터 정합해야 하며, 양자화된 미세 선분을 먼저 버리면 닫힌 고리가 끊어질 수 있었다. 방향 경계를 소거한 뒤 공통 격자로 한 번 노딩한다. [단면 검사](../../src/topo/checks/core/ContourSectionChecks.cs)는 해석적 면적·임계 고도·서로 다른 세분 수를 검증한다.

종로의 연속 Near에서는 같은 점에 모인 여러 변을 공간적 Join이 구분하지 못해 상면과 외벽이 열렸다. 외벽의 trim에 원본 상면의 변 분할을 보존하고 이미 아는 변 쌍을 직접 연결했다. 상면 Join이 면 ID와 입력 대응을 지울 수 있어 사본의 지지면에 작업 중 표식을 두어 표시망을 전달한 후 제거한다. 표시 고리 역시 원본 면 소유권을 유지한다. `JongnoJunction` 재생과 [형상 보조 검사](../../src/topo/checks/native/SurfaceHelperChecks.cs)가 이 연결을 보호한다.

Near의 가까운 지지선을 사후 추정하면 유한 직선과 원호의 연결이 바뀌고 양의 단면이 왕복 선분으로 퇴화할 수 있었다. 이를 원본 직선·원호의 유한 교점과 공유 사건으로 경계를 구성하는 방식으로 교체했다. 같은 격자 칸의 다른 교점은 합치지 않고, 원호 끝점 밖의 지지 원 교점은 제외한다. 서로 다른 유한 교점이 같은 double 좌표로 표현되는 작은 영역은 원래 유리 좌표에서 면적을 판정한다. 접촉 단면도 실제 공유점의 방향 경계로 분리하며 재삼각분할하지 않는다. 같은 직선 위의 연속 구간은 합치되 서로 다른 실제 교점은 지우지 않는다. 개별 LineCurve·ArcCurve로는 무효가 되는 짧은 구간도 있으므로 직선 연결부는 1차 NURBS, 짧은 원호와 인접 구간은 정확한 유리 2차 NURBS로 묶는다. 일반 원호는 ArcCurve로 유지해 불필요한 형상 처리 비용을 줄이며 실제 교점과 원호를 생략하지 않는다. 실제 Extrusion의 폐합·체적은 [프로파일 검사](../../src/topo/checks/native/ContourChecks.cs)로 확인한다. [유한 경계 검사](../../src/topo/checks/core/ExactNearRegionsChecks.cs), [접촉 건물 검사](../../src/topo/checks/native/BuildingContactChecks.cs).

원시 NonZero 선 목록을 다른 단계에서 정상 외곽·구멍으로 해석하면 자기교차·음의 ring의 소유권이 달라졌다. 진입점에서 고정 격자 노딩과 소유권을 확정하고 반복 overlay에는 영역을 유지한다. 표본을 격자로 옮긴 뒤에도 새 교차가 생길 수 있으므로 삼각분할 전에 정규화한다. Extrusion 자체의 `IsValid/IsSolid`가 퇴화 프로파일을 허용한 사례는 프로파일 면적과 실제 Brep 변 연결·양의 체적을 준비 단계에서 검사하도록 반영했다.

Contour 겹침 도로에서는 판과의 교차가 전처리 이후 새 미세 조각을 만들 수 있어 같은 노출판 안에서 공통 최소 상세 재배분을 적용한다. 정상 경계에도 가까운 정점은 남을 수 있으므로 이미 아는 외곽·구멍으로 평면 trim을 직접 만들고, 표시망은 삼각분할 정점 ID를 유지한다. Rhino의 사후 정점 병합은 서로 다른 1µm 정점을 합쳐 면을 깨뜨릴 수 있었다. Far Mesh 결합도 공통 double 좌표 작성기를 사용해 정확히 같은 정점만 공유한다. [평면 검사](../../src/topo/checks/core/ContourChecks.cs)와 [겹침 도로 검사](../../src/topo/checks/native/ContourOverlayChecks.cs)가 역할 변경·m/mm·이동·방향 반전을 확인한다.

## 2026-10-10 · 계산 실패와 원천 제외의 구분

넓은 예외 처리가 건물 내부 계산 실패까지 원천 불량으로 바꿀 수 있어 원천 검증 예외를 분리하고 생성 대상과 출력 식별자를 대조한다. 도로 솔버의 고정 반복 상한을 넘어야 수렴하는 조건이 나쁜 입력은 [독립 직접해 검사](../../src/topo/checks/core/RoadSolverChecks.cs)로 재현했다. 실제 잔차·제약 수렴과 자원 한도를 구분하며 미수렴 보정을 성공 경고로 남기지 않는다.

## 2026-10-10 · Contour 외벽과 생성 중간 결과의 재사용

노출판마다 Near 경계를 나누어 높이 차이를 Mesh로 막던 경로를 제거했다. 정확 원호·접선을 연속 지형에 직접 올리고 기단 윗면까지 수직 NURBS 외벽으로 내린다. 판 옆면과 겹침을 허용하므로 판별 연결과 높이차의 부호 탐색이 필요 없다. 외벽의 상단 도로 판정에는 전체 공유 평면의 도로를 사용한다. Contour 범위로 다시 자른 도로는 교점 반올림으로 Far와 전환점이 달라질 수 있었다. [외벽 검사](../../src/topo/checks/native/ContourWallChecks.cs)와 [Contour 검사](../../src/topo/checks/native/ContourChecks.cs)가 정확 경계·높이·도로 전환을 보호한다.

Contour에서 출력하지 않는 Near 연속면의 삼각분할·높이 정제·패치 생성을 제외하되 전체 평면 피복과 Far 경계 복원 자료는 유지했다. 판의 독립 단면, Near 건물 겹침 묶음, 같은 바닥 단계의 기초 구멍 합집합과 노출영역 범위를 생성 안에서 재사용한다. 기초 바닥이 바뀌면 해당 합집합도 새로 계산한다. [Far 출력 검사](../../src/topo/checks/native/FarSurfaceChecks.cs)는 Near 생략 전후의 Far 형상·도로 옆면·면적을 비교한다.

## 2026-10-09 · 굴착을 Contour 평면 계산에 통합

곡면 지형을 건물 윤곽으로 파는 과정에서는 평면 그래프와 실제 NURBS 상면의 분할·벽 대응이 달라질 수 있었다. 원본 경계 보존, 공유 수직 분할, 바닥의 1m 여유를 적용하고 Rhino BooleanDifference도 비교했으나, 굴착과 표시망의 안정성을 함께 다뤄야 했다. 이 경로는 제거하고 선택적 Contour의 평면 단면 차집합으로 굴착을 통합했다. 판은 일정 단면의 Extrusion으로 만들며 작은 돌출은 생략해 아래 레벨을 드러낸다. 선택 대지는 계단화하지 않고 별도의 곡면 입체로 보존한다. 현재 규칙과 검사는 [계약](contract.md)과 [검사 안내](../../src/topo/checks/README.md)에 둔다.

건물은 원본과 정리 윤곽 모두 Near 내부에 있을 때만 Near로 취급한다. 경계 접촉·교차 건물은 Far로 남겨 근접 경계가 건물 굴착을 가르지 않게 한다. 유효한 겹침 건물을 제외하던 처리는 폐기하고, Near의 면적 중첩 묶음은 낮은 기초 바닥을 공유하되 각 건물과 지붕을 유지한다.

판 굴착 뒤 작은 잔여부를 생략하면 비굴착 건물 아래의 지반도 낮아질 수 있다. 최초 통계만으로 기초를 확정하지 않고 실제 남은 판과 바닥을 함께 맞춘다. 굴착을 공유하는 묶음에는 자기 굴착 바닥에서 다시 1m를 빼지 않아 반복적인 하강을 막는다.

평면 차집합을 연쇄 처리하면서 생긴 미세한 재노딩 잔여부가 정확 원호 복원과 점 접촉 단면을 불안정하게 만들었다. 반복 단순화 대신 기존 1µm 격자의 고정 정밀도 부울 연산과 NonZero 합집합으로 노딩·구멍 의미를 통일했다. 원본 단면과 Near 표시 단면을 독립적으로 차집합하면 서로 다른 결과가 짝지어질 수 있어, 원본을 한 번 확정한 뒤 Near를 파생한다. [정밀도 검사](../../src/topo/checks/core/ContourPrecisionChecks.cs)는 실제 작은 입력·구멍 보존·반복 정규화·이 원본 관계를 보호한다.

## 2026-10-08, 2026-10-09 · Near 분할의 작은 역할 영역 정리

원천 도로가 최소 크기를 충족해도 Near 경계로 나누거나 공통 평면 그래프에서 교차점을 연결하면 작은 독립 땅·도로 조각이 생겼다. 사전 정리만으로 완료됐다고 판단하고 이후 조각을 오류로 거절하는 방식은 정상 입력을 처리하지 못했다.

원천의 50mm 정리 후 잔여 조각과 Near/Far 분할 조각 모두 원본 XY·출력 구역을 고정하고, 작은 역할 조각을 같은 구역에서 가장 긴 경계를 공유하는 이웃으로 재배분한다. 이 처리에는 이전의 50mm 변경 띠 제한을 적용하지 않는다. 변경 면적은 계산 결과에 남긴다. [Near 도로 검사](../../src/topo/checks/core/NearRoadChecks.cs)와 [공통 평면 검사](../../src/topo/checks/core/PlanarPartitionChecks.cs)가 사전 정리와 최종 분할 양쪽을 보호한다.

역할 재배분 전 도로로 건물 높이를 계산하면 실제 출력과 다른 지반을 참조할 수 있다. 공유 평면을 먼저 확정하고 건물·Contour·연속 지형이 함께 사용한다. 이때 출력 밖에 확보한 도로는 전체 건물 지반 통계를 위해 보존한다.

## 2026-10-08, 2026-10-09 · 출력 범위와 건물 지반 취득 분리

출력 범위로 높이장까지 제한하면 경계 건물마다 추가 범위를 요구하게 됐다. 생성 대상 건물은 최초 출력 범위 응답으로 한 번 확정하고, 그 전체 지반에 필요한 필지·DEM만 추가 취득한다. 넓어진 범위로 건물을 다시 조회하지 않으므로 대상이 연쇄적으로 늘지 않는다. 모든 생성 건물에 전체 지반 통계를 적용하며 Far의 중심점 배치는 제거했다.

출력 내부의 도로 정리와 범위 밖 건물의 지반에는 같은 도로 보정 높이장을 사용한다. 출력 경계를 위해 DEM을 다시 표본화하거나 누락 높이를 연장하지 않는다. 전체 건물 통계에서 도로 전체를 매번 교차시키는 비용을 줄이기 위해, 원본 구멍을 보존한 도로 성분의 공간 인덱스와 준비된 교차 판정으로 실제 후보만 적분한다. 전체 교차 방식과 최저점·평균의 동등성을 검사한다. [취득 범위 검사](../../src/topo/checks/core/TerrainCoverageChecks.cs), [서비스 검사](../../src/topo/checks/service/TerrainCoverageServiceChecks.cs), [출력 검사](../../src/topo/checks/native/CoverageGeometryChecks.cs).

## 2026-10-07, 2026-10-08, 2026-10-09 · 지반 통계와 NURBS 경계의 수치 안정성

건물 윤곽을 DEM 셀마다 다시 1µm 격자로 자르면 교차점 반올림 때문에 합산 면적이 달라졌다. 통계용 교차점은 robust overlay로 계산한 뒤 쌍선형 높이를 적분하며 전체 윤곽 면적 검증을 유지한다. 잘린 조각 면적으로 결과만 정규화하면 누락을 숨길 수 있다. [지반 통계 검사](../../src/topo/checks/core/BuildingPlacementChecks.cs).

평지의 중복 NURBS 구간 위에 원호·구멍을 trim하면 Rhino 면적·체적 적분이 실패하는 사례가 있었다. 같은 지형을 나타내는 선형 구간만 합치고 실제 꺾임은 남긴다. 공유 경계는 원본 유한 선분의 출처와 계산 순서를 유지한다. 거의 평행한 반환 선분을 다시 교차시키면 작은 끝점 차이가 큰 위치 오차로 증폭되므로, 두 조각의 실제 원본 모서리가 공유하는 정점부터 복원한다. 닫힌 경계는 정점의 연결 수만이 아니라 실제 면의 edge/trim 연결로 읽는다. [지지면 검사](../../src/topo/checks/native/SurfaceHelperChecks.cs), [원본 경계 검사](../../src/topo/checks/core/PlanBoundarySourcesChecks.cs), [면적 검사](../../src/topo/checks/native/AreaIntegralChecks.cs).

정확한 NURBS 꺾임과 표시망의 격자 연결변은 서로 다른 국소 접선을 가지므로 둘의 법선 내적만으로 뒤집힘을 판정하면 정상 벽도 실패한다. 위치 근사와 방향 판정을 구분하고 두 표현의 폐합·공유변 방향·부호 있는 체적을 독립 검증하며, 작은 코너와 실제 반전 입력을 [형상 보조 검사](../../src/topo/checks/native/SurfaceHelperChecks.cs)에 둔다.

## 2026-10-05 · 100mm 기준을 모델 평면에만 적용

원천 경계의 작은 돌출·틈·조각이 편집하기 어려운 미세 면과 입체, 잘못된 수직 벽으로 이어졌다. 사용자가 허용한 100mm 기준을 모델용 평면 전처리에 적용하되 원본 XY Curve는 그대로 남기기로 했다.

모든 방향의 작은 형상을 없애는 규칙으로 해석하면 사용자가 설정한 50mm 도로 내림까지 사라진다. 이를 피하려고 평면 정리와 높이 처리를 분리했다. 정리 조건을 충족하지 못한 조각을 조용히 삭제하거나 지역별 보정을 추가하는 방식은 택하지 않았다. [평면 정리 검사](../../src/topo/checks/core/ModelPlanChecks.cs), [지형·단차 검사](../../src/topo/checks/native/ModelGeometryChecks.cs).

## 2026-10-05 · 주변 Projected 참조선을 제거하고 정보 밀도를 구분

주변 필지·도로·건물에 XY와 투영 Curve를 모두 생성하는 구조는 정보와 형상을 중복시켰다. 주변 원본은 XY만 남기고 설계 대상의 대지경계만 지형에 투영하기로 했다. Near 여부 때문에 원본 참조선 생성 경로가 달라지지 않도록 공통화했다.

정보도 모델 전체에 같은 상세도를 적용하지 않고 설계 대상과 주변 문맥을 구분했다. 병합된 땅·도로 면에는 원필지를 억지로 집계하지 않았고, 생성 당시 같은 정보를 쓰는 건물 XY·입체에도 편집 후 자동 동기화 책임을 만들지 않았다. 현재 상세도는 [정보 계약](contract.md#객체-정보와-후속-도구), 재현은 [원본 참조선 검사](../../src/topo/checks/native/SourceReferenceChecks.cs)와 [객체 정보 검사](../../src/topo/checks/core/ObjectInfoChecks.cs)에 있다.

## 2026-10-05 · 원천 데이터의 불일치를 형상 보정으로 숨기지 않음

건물과 필지가 어긋나 보이는 문제와 실제 지상에 없는 추정 건물을 조사했다. 건물 윤곽을 주변 필지에 맞춰 이동·축소·절단하면 원천의 차이를 모델링 오류로 바꾸므로 채택하지 않았다. 지하 시설은 같은 feature ID와 건물관리번호가 확인되는 분류 응답으로만 제외한다. 이름·층수 0·주변 위치만으로 지하를 추정하는 방식은 쓰지 않았다.

주소 역시 기존 VWorld 응답에서 얻은 범위만 기록한다. 상세 정보가 필요하다는 이유로 별도 주소 조회나 PNU 기반 주소 추정을 추가하지 않았다. 더 풍부한 정보의 취득은 다른 도구가 맡을 수 있도록 Topo의 경계를 정했다. [데이터 의미와 제약](../../docs/topo/data.md), [건물 분류 검사](../../src/topo/checks/core/BuildingClassificationChecks.cs).

## 2026-10-05 · DEM 취득은 실험 경로라는 한계를 유지

사용자별 회원 로그인, 미리 확보한 지형 DB, 지역마다 달라지는 취득 규칙은 공개 Rhino 플러그인의 목표에 맞지 않았다. 실행 시 사용자의 VWorld KEY로 요청하는 방식으로 좁혔고, 공개 3D 지도 SDK의 DEM 전달 경로를 재현하는 어댑터를 사용했다.

이 경로를 공식 독립 DEM 다운로드 API로 확정한 것은 아니다. 공식 지원·수직 기준·모델 가공 및 제공 조건은 확인되지 않았으며 원본 등고선·수치지형도를 키만으로 얻는 기능도 아니다. 누락 타일을 0이나 다른 레벨로 대체하면 사용자가 실패를 알 수 없으므로 중단하도록 했다. 공식 공급 경로나 이용 조건이 확인되면 취득 방식을 다시 검토할 필요가 있다. [현재 취득 경로](../../docs/topo/data.md), [지형 취득 검사](../../src/topo/checks/core/TerrainChecks.cs).

## 2026-10-05 · 작은 구간의 수치 오류를 계산식에서 수정

길이가 극히 작은 NURBS 구간이 포함되면 전체 구간에서 직접 적분하는 방식의 오차가 면적·방향 판정을 흔들었다. 정확한 Bézier 구간을 추출하고 국소 좌표와 정규화된 매개변수로 적분하도록 고쳤다. 별도로 같은 원 위의 점들이 부동소수점 오차 때문에 서로 안쪽이라고 번갈아 판정되어 삼각분할 대각선 교환이 끝나지 않는 문제가 있었다. 모호한 경우에는 원래 double 값을 정확한 이진 유리수로 취급하는 판정을 사용했다.

두 문제 모두 허용오차 확대나 특정 지역 예외로 피하지 않았다. 작은 합성 입력과 이동·m/mm·경계 방향 변환 검사를 남겨 원인을 재현한다. [면적 회귀 검사](../../src/topo/checks/native/AreaIntegralChecks.cs), [동일 원 판정 검사](../../src/topo/checks/native/InCircleChecks.cs).
