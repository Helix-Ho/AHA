# EumCrawl History

필요한 과거 판단을 찾아 읽는 기록이다. 현재 책임은 [개발 README](README.md), 동작의 약속은 [계약](contract.md), 기록 방법은 [History 기록 기준](../README.md#history-기록-기준)을 따른다. 아래 2026-10-05는 이전 개발 과정을 정리한 날짜이며 실제 결정일을 뜻하지 않는다.

## 2026-10-07 · 수치 후보와 원문 읽기를 별도 호출로 제공

최솟값 후보는 간단한 초기 계획에 유용하지만 조건별 수치를 직접 읽으려는 호출자에게는 부족했다. 원문 결과에 후보 선택 정책이 섞이지 않도록 HTTP 취득을 공유하면서 표·조건·문단을 보존하는 읽기 기능을 분리했다.

긴 응답을 잘라 조건이 사라지는 것을 피하려고 한도 초과는 항목 실패로 드러내기로 했다. 브라우저 화면의 복제나 법규 판단으로 확대하지 않은 범위는 [원문 읽기 계약](contract.md#원문-구조-읽기)에 있다.

같은 응답 안에서도 도식의 0%와 면적의 0㎡는 실제 규제가 아니라 JavaScript 실행 전 초기값이었다. 공식 `fn_calArea`와 `fn_showAreaData`가 해당 DOM을 계산 결과로 교체함을 확인해, 숫자 0을 일괄 제거하는 대신 해당 영역을 미확인으로 구분했다. 근거는 [공식 화면 스크립트](../references/Eum/README.md), 규제 표의 실제 0%와 구분하는 재현은 [원문 구조 검사](../../src/eum-crawl/checks/EvidenceChecks.cs)에 있다.

## 2026-10-05 · 조회와 적용을 분리하고 PNU 조회에 집중

EumCrawl을 Topo의 후속 입력 단계에 종속시키지 않고 독립 조회 도구로 정리했다. 객체가 없어도 조회할 수 있고, 객체가 있으면 기존 값과 비교해 선택한 항목만 반영한다. 주소만으로 PNU를 찾는 흐름은 추가 데이터와 검색 절차가 필요하므로 현재 범위에 넣지 않았다.

다른 PNU를 조회했더라도 주소·PNU 항목을 선택하지 않으면 기존 식별정보는 그대로 남기는 것으로 결정했다. 조회한 대상과 저장 객체의 식별정보가 달라지는 조합도 사용자의 명시적 선택이므로 자동 정정하지 않는다. [EumApply](../../src/eum-crawl/shared/EumApply.cs)와 [EumNativeChecks](../../src/eum-crawl/checks/native/EumNativeChecks.cs)에 이 선택 적용과 나머지 필지·확장 정보 보존을 담았다.

## 2026-10-05 · 건폐율·용적률을 관찰된 최솟값으로 제공

조건별 수치와 겹친 용도지역의 수치 때문에 크롤링 결과만으로 하나의 허용값을 확정하기 어려웠다. 텍스트만 저장하는 대신, 사용자는 해당 건폐율·용적률 조례 항목에 보이는 백분율의 최솟값을 숫자로 쓰는 방식을 선택했다. 현재 후보 범위와 미확인 처리 기준은 [수치 계약](contract.md#수치와-필지-정보)에 둔다.

이 선택은 법규 적용성 판단이 아니다. 선택 방식과 한계, 원문 열람 경로를 패널과 MCP에 남겼고 높이·층수·이격까지 같은 최솟값 규칙으로 확대하지는 않았다. [EumParser](../../src/eum-crawl/shared/EumParser.cs)와 [파서 검사](../../src/eum-crawl/checks/Program.cs)에 조건·범위·중첩 수치와 숨긴 숫자를 구분하는 재현 입력이 있다. 원문 구조가 바뀌거나 별도의 적용성 판단 도구를 만들 때 다시 검토할 수 있는 경계다.

## 2026-10-05 · 미리보기의 대상과 수명을 적용 시점까지 보존

조회와 적용을 나누면서 지연 응답, 다른 문서의 같은 GUID, 변경된 필지 슬롯, 호출자가 바꾼 결과를 잘못 적용할 가능성을 검토했다. 미리보기를 문서·객체·필지 슬롯·원본 속성에 연결하고, 적용에는 서버가 보관한 원본 결과만 사용하게 했다. 적용 후에는 같은 결과를 다시 쓰지 않는다.

캐시 용량 확인과 등록을 따로 수행하면 동시 조회가 한도를 넘을 수 있음을 확인하여 한 임계영역으로 묶었다. 현재 한도·만료·소비 규칙은 [미리보기 계약](contract.md#미리보기-수명과-실패), 대상 보존과 경합의 재현은 [EumNativeChecks](../../src/eum-crawl/checks/native/EumNativeChecks.cs)에 있다. 선택·입력 변경 뒤 도착한 패널 응답의 폐기는 [EumPanelChecks](../../src/eum-crawl/checks/native/EumPanelChecks.cs)에서 재현한다.
