# Topo 데이터와 한계

## 현재 호출 경로

모든 요청은 Setting에 저장한 사용자의 VWorld 키로 실행 시 직접 호출한다. 클라우드 AHA 서버, 사전 지형 DB, 회원 브라우저 로그인은 사용하지 않는다. 선택적 로컬 MCP도 동일한 취득 기능을 호출한다.

| 용도 | 엔드포인트·서비스 | 사용하는 내용 |
| --- | --- | --- |
| 배경지도 | `api.vworld.kr/req/wmts/1.0.0/{key}/Base/{z}/{y}/{x}.png` | 지도 표시용 PNG |
| 주소 검색 | `api.vworld.kr/req/search`, `type=ADDRESS`, `category=ROAD/PARCEL` | 주소 후보·좌표·PNU |
| 선택 필지 | `api.vworld.kr/req/data`, `LP_PA_CBND_BUBUN` | POINT 또는 PNU 필터의 필지 도형·PNU·지번주소 |
| 범위 내 필지 | `api.vworld.kr/ned/wfs/getCtnlgsSpceWFS`, `dt_d002` | 연속지적도 도형·PNU·지번 지목 원문 |
| 건물 윤곽·속성 | `api.vworld.kr/req/data`, `LT_C_SPBD` | 건물 도형·관리번호·층수·명칭·도로명·주소 구성요소 |
| 건물 지상·지하 분류 | `api.vworld.kr/req/wfs`, `lt_c_spbd` | 정확 feature ID의 `bd_mgt_sn`, `buld_se_cd`, `gro_flo_co`, `und_flo_co` |
| 지형 인증 | `map.vworld.kr/dtkmap/selectApiKeyJson.do` | 사용자 키를 SDK 요청용 인증값으로 교환 |
| 지형 격자 | `xdworld.vworld.kr/XDServer/3DData`, `Request=GetLayer`, `Layer=dem`, `Version=2.0.0.0` | Level/IDX/IDY에 따른 65×65 표고 배열 |

지형 두 경로는 **공개 3D 지도 SDK의 전달 방식을 재현한 실험 어댑터**다. 공식적으로 지원되는 독립 DEM 다운로드 API로 소개하지 않는다. 공식 지원, 수직 기준, Rhino 모델 가공·저장·제공의 이용 조건은 확인이 필요한 상태다. 원본 등고선·수치지형도 파일을 키만으로 취득하는 기능은 구현하지 않았다. [공식 SDK](https://map.vworld.kr/js/ws3dmap/WS3DRelease3/VWViewerStartup.v30.min.js), [SDK 지도 설정](https://map.vworld.kr/js/ws3dmap/WS3DRelease3/json/vworld.json), [VWorld DEM API 안내 답변](https://www.vworld.kr/v4po_brdqna_s002.do?brdIde=33492&bodIde=53), [이용약관](https://www.vworld.kr/v4po_prcint_a001.do).

공식 명세: [검색](https://www.vworld.kr/dev/v4dv_search2_s001.do), [지적도 Data API](https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=cadastral), [연속지적도 WFS](https://www.vworld.kr/dtna/dtna_apiSvcFc_s001.do?apiNum=92), [도로명주소 건물](https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=spbd), [WFS 안내](https://www.vworld.kr/dev/v4dv_wmsguide2_s001.do).

PNU는 정보 밀도와 무관하게 확보한 값을 보존한다. 대상 대지경계·Contour 대지 본체와 그 XY 원본은 항상 상세 정보이며 선택 응답의 지번주소를 유지한다. 주변 필지·도로 필지의 XY 경계는 기본 정보로 PNU·지번 표기·지목 코드를 기록한다. 근접 모델링을 켜면 최종 근접영역과 겹치는 필지에 이미 확보한 지번주소가 있을 때 함께 기록한다.

정보 기록을 위한 별도 주소 조회는 하지 않는다. 기존 선택·모델 생성 응답에 주소가 없으면 상세 정보에서도 비워 둔다. 지번 표기나 PNU를 해석해 전체 주소를 추정하지 않는다.

건물은 이미 받는 응답에서 상세 속성을 보존하므로 정보 밀도를 위한 추가 요청이 없다. 기본 정보는 확보한 건물관리번호·PNU·지상층수·모델 높이·높이 산정 근거·분류 상태다. Near로 생성되는 건물은 건물명·동 명칭·영문명·도로명·도로명주소·지하층수·지상/지하 코드를 추가한다. 명시적 `addr`만 `data.parcels[].address`로 저장하며 도로명주소는 `data.road_address`로 구분한다. 시도·시군구·도로명·건물번호가 모두 있을 때 원천 구성요소를 조합하고, 부족하면 확보한 구성요소만 기록한다. 읍면(`gu`)은 있을 때만 포함한다. 건물 PNU는 응답에 명시된 유효한 값만 쓰며 관리번호에서 잘라 만들지 않는다.

생성한 건물의 본체·기초·XY 윤곽에는 같은 밀도와 정보를 기록한다. XY 전용 결과나 입체가 없는 원본 참조선에는 모델 높이·높이 산정 근거를 넣지 않는다. 근접영역 경계에 닿거나 걸쳐 Far로 생성되는 건물은 기본 정보다. 땅·도로 면과 입체는 병합 원필지의 정보를 모으지 않고 `kind`만 기록한다. 필지 지번주소나 건물 도로명으로 합쳐진 도로면의 이름을 추정하지 않는다.

## 도로와 건물의 의미

도로는 같은 연속지적도 필지의 지목 표기로 분류한다. NED의 `lnm_lndcgr_smbol`과 Data API의 `jibun` 원문을 보존하고 ‘도’를 지목 코드 14로 정규화한다. 누락·해석 실패는 미확인이며 PNU나 이름으로 추정하지 않는다. 원본 도로 영역과 비도로·미확인 필지가 겹치면 해당 부분은 땅으로 남기고 중첩·형상 복구량을 기록한다.

이 도로는 **등록된 도로 부지**다. 실제 차도·보도·잔디·광장·포장 경계와 같지 않으며 교량·터널 높이도 나타내지 않는다. 특정 장소나 필지 번호의 예외 규칙은 없다. 도로 폭을 중심선에서 추정하지 않는다.

XY의 건물 윤곽과 중정은 `LT_C_SPBD` 원본을 모델 범위에서 잘라 보존한다. 건물 입체·Contour 굴착에 사용하는 모델 윤곽은 [100mm 평면 정리](README.md#주요-설정)를 적용한다. WFS 분류는 feature ID와 건물관리번호가 모두 일치할 때만 보강한다. 공식 `buld_se_cd=1`은 지하, `0`은 지상이며 확인된 지하 시설만 지상 입체에서 제외하고 참조 Curve에 상태를 남긴다. 층수 0·건물명·공간 근접성으로 지하를 추정하지 않는다. [공식 건물 구분 설명](https://eng.juso.go.kr/addrlink/qna/qnaDetail.do?bulletinRefSn=113627&noticeMgtSn=113627&noticeType=QNA).

원본 건물에 분류용 식별자가 없거나, 완전한 분류 응답에 해당 객체·분류 코드가 없으면 미확인으로 기록하고 높이를 추정한다. 반환된 분류 객체의 식별자가 누락되거나 원본과 일치하지 않는 경우, 통신 실패·응답 불완전·취득 사이 층수 불일치는 생성을 중단한다. 분류 WFS의 좌표로 Data API 윤곽을 교체하지 않는다.

현재 건물 원천에는 실높이가 없어 양수 지상층수×층당 높이, 그 외는 기본 높이를 쓴다. 모든 생성 건물의 지붕은 전체 윤곽 아래 연속 지형의 면적 가중평균+원천·추정 높이다. 일반 기초는 전체 최저점보다 1m 아래다. Contour로 굴착하는 Near 건물은 실제 노출판들의 최저 바닥을 적용한다. 이는 실제 기초·지하층·성토·절토 자료가 아니다. 급경사에서 건물 상부가 지형에 묻힐 수 있다.

원천과 정리된 윤곽이 모두 근접 경계 안에 있고 닿지 않아야 Near 건물이다. 닿거나 가로지르면 전체를 Far로 만든다. 건물과 필지는 작성 기준·갱신 시점이 다르며 한 건물이 여러 필지에 걸칠 수 있다. 이를 맞추려고 건물을 이동·축소하지 않는다. 유효한 겹침 건물도 유지한다.

건물의 전체 도형 중심이 모델 범위 안에 있으면 전체 윤곽을 생성하므로 일부가 사각 범위 밖으로 나올 수 있다. Near 여부와 관계없이 전체 지반에 필요한 필지·DEM을 내부적으로 더 취득한다. 넓어진 범위의 건물을 다시 수집하지 않으며 지형·도로·XY 출력은 지정 범위 안에 둔다. 유효하지 않은 원천 윤곽과 최소 상세 기준으로 제외한 모델 윤곽은 식별자와 이유를 남기고 유효한 XY는 보존한다. 내부 계산 실패를 원천 불량으로 간주해 생략하지 않는다. 생성 대상으로 확정한 유효 건물의 출력 실패를 조용한 제외로 처리하지 않는다.

## 좌표와 고도

- API 도형은 WGS84 경도·위도를 사용한다. 모델 XY는 조회 범위 중심을 원점으로 한 지역 근사 좌표이며 내부 길이 단위는 m다. 정식 측량 좌표계 변환이나 지적측량 성과가 아니다.
- 원본 DEM의 표고 값을 유지하고 **대지 중심 높이를 빼서 Z=0으로 만들지 않는다.** 다만 공급 표고의 수직 기준은 확인되지 않았으므로 정확한 해발고도로 단정하지 않는다.
- 도로 횡단 경사 보정은 원본 DEM 노드의 변화를 최대 ±3m로 제한한다. 땅·도로·건물 배치가 같은 최종 높이장을 사용한다. 도로를 내리는 설정은 그 높이에서 별도로 단차를 뺀다.
- 연속 Near 바닥은 상면 전체 최저점에서 설정 깊이만큼 내린 공통 수평면이다. Contour는 도로 단차·굴착·대지 최저 높이를 포함한 최저 상세 레벨 아래에 지지판 2장과 기단을 둔다. 깊이는 지반조사·굴착 설계 값이 아니다.
- 원본 XY Curve는 Z=0이다. Contour OFF의 투영 대지경계는 보정된 땅·도로 높이와 단차를 따르며 폐합을 유지한다. Contour ON은 투영 Curve 대신 곡면 상면의 대지 본체를 제공한다.
- 지형·건물·Curve는 최종 단계에서 Rhino 문서 단위로 변환한다. 생성 묶음의 상위 레이어에는 지리 원점과 출력 범위를, 개별 객체에는 해당 높이·추정 방식을 기록한다.

Contour는 DEM 높이장을 판으로 표현한 모델이며 원천 등고선 자료가 아니다. 작은 등고 돌출을 생략하고 계단 레벨로 표현하므로 연속 지형과 외형이 다르다. 간격·범위·높이 변화에 따른 처리량을 사전 검사하고 간격을 임의로 늘리지 않는다.

공통 높이장의 쌍선형 보간은 셀의 표고 범위를 넘는 새 봉우리·골짜기를 만들지 않지만 실제 지형의 정답은 아니다. 격자 사이의 연석·옹벽·좁은 계곡 등은 표현할 수 없다. 도로 보정도 모델링 추정이며 실제 종단·횡단 측량이나 절성토량을 대신하지 않는다.

## 완전 수집과 실패 처리

필지 WFS는 응답 한도를 넘으면 동일 규칙으로 범위를 분할하며 전체 건수·중복을 검사한다. 건물 Data API는 공간 분할과 페이지를 끝까지 수집하고 분류 속성을 묶음 조회한다. 잘린 응답을 완전한 결과로 사용하지 않는다.

현재 지형 요청은 고정 레벨이며 최대 64타일·높이 표본 100만 개를 사전 검사한다. 모든 생성 건물에 필요한 추가 지반도 이 한도와 자료 검증을 적용하므로 출력 범위가 작아도 큰 건물 때문에 취득량이 늘 수 있다. 데이터가 없는 타일이나 잘못된 격자는 실패로 처리하고 다른 레벨로 조용히 대체하지 않는다. 필지·건물은 전체 건수까지 수집하며, 원천 응답이 불완전하거나 같은 위치의 자료를 API 응답 제한 안에서 분리할 수 없으면 취득 실패다. 주소 검색은 후보 목록이며 전국 주소 전체를 열거하는 수집기가 아니다.

한국 전체에 같은 요청·분류·모델링 규칙을 적용하지만, 표본의 성공이 전국 데이터 완전성이나 모든 레벨의 가용성을 보장하지 않는다. 서버·키 권한·자료 갱신에 따라 응답이 달라질 수 있다.

## 키 보안과 지원 범위

키는 [Setting](../setting/README.md)의 마스킹된 입력과 운영체제 보안 저장소에서만 관리하고 요청은 C#에서 처리한다. 환경변수나 `.env`는 자동으로 읽지 않는다. 실제 키·SDK 인증값을 지도 HTML, Rhino 파일, 오류 메시지나 보고서에 넣지 않는다. HTTP 자동 리다이렉트와 쿠키는 사용하지 않는다.

현재 Topo 결과는 초기 대지 검토와 주변 맥락 모델을 위한 것이다. 규제·허용 건폐율/용적률 판정, 측량 수준의 정확도, IFC/BIM 설계, 임의 편집 후 자동 갱신은 포함하지 않는다. 토지이음의 참고 규제 자료 조회는 별도 실험 도구인 [EumCrawl](../eum-crawl/README.md)이 맡는다. 큰 모델의 표시 속도와 저장 크기는 지형뿐 아니라 건물·참조 Curve·표시 Mesh의 양에도 좌우된다.
