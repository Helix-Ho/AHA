# Topo 설계 변경과 검증 기록

기준: AHA 0.0.1 · 확인: 2026-10-12

Topo는 선택 필지와 주변 범위의 필지·건물·높이 자료를 받아 Rhino의 지형·도로·건물과 평면 참조선을 만든다. 이 글은 주요 설계 변경, 결함의 원인, 검증과 성능 측정을 주제별로 정리한다. 같은 0.0.1 안의 변경을 다루므로 비교 대상은 버전 번호 대신 각 실험의 계산 방식으로 구분한다.

| 용어 | 의미 |
|---|---|
| XY | 원천 필지·도로·건물 윤곽을 Z=0에 남긴 평면 참조선. 모델용 상세 정리와 구분한다. |
| Near | 선택 대지 주변의 편집용 영역. 연속 지형은 닫힌 NURBS 입체, 건물은 Extrusion으로 만든다. |
| Far | Near 밖의 주변 문맥. 지형·건물을 Mesh 또는 편집 가능한 형식으로 만든다. |
| Contour | Near의 주변 지형을 일정 높이 간격의 판으로 표현하는 선택 기능. 판은 Extrusion이며 선택 대지는 곡면 입체로 유지한다. |

Mesh는 삼각형 등의 면으로 이루어진 망, NURBS는 수학적으로 정의한 곡선·곡면이다. Extrusion은 일정한 평면 단면을 직선으로 돌출한 경량 형식이며, Brep는 면·변의 경계 연결로 형상을 표현한다.

높이 자료는 수치표고모델(DEM)의 표본이다. 타일은 공급원이 자료를 나누어 전송하는 공간 단위, 셀은 높이 표본을 잇는 격자 한 칸이다. 원본 등고선이나 측량 성과를 입력받는 방식은 아니다. 내부 좌표는 지역 원점의 동·북 방향 m이며 Rhino 문서 단위로 변환한다. 정식 측량 좌표계 변환이나 공급원의 수직 기준을 보장하지 않는다.

## 1. 원천 자료와 모델 표현의 분리

**문제와 영향.** 지적도에는 건축 모델에서 다루기 어려운 작은 돌출·틈·겹침이 있다. 이를 입체에 그대로 옮기면 미세 면이 늘고, 원본까지 정리하면 사용자가 취득 자료와 모델의 차이를 확인할 수 없다. 주변 윤곽을 XY와 지형 투영선으로 모두 만들면 같은 정보의 객체도 중복된다.

**검증.** 합성 필지·도로·구멍·작은 조각에서 원천 참조선과 모델용 평면을 별도로 확인했다. 범위를 가로지르는 원천 선은 잘리더라도 범위 끝에 가짜 닫힘 선이 생기지 않아야 한다. 작은 평면 상세를 정리해도 50mm 도로 내림 같은 수직 단차는 남아야 한다. Mesh/NURBS, Near ON/OFF와 XY 전용 실행에서 이 구분을 검사했다.

**원인.** 원천 경계, 입체 계산용 영역, 사용자 참조선을 같은 표현으로 취급했다. 도로 중심선에 추정 폭을 주던 방식도 지적 필지와 독립적으로 계산되어 주변 필지를 관통할 수 있었다.

**변경.** 원천 XY는 모델 정리 없이 보존하고, 입체 평면에만 최소 폭 100mm·작은 영역 0.01㎡ 기준을 적용했다. 일반 정리는 원래 경계 주변 50mm 변경 띠 안에서 수행한다. 이후 분할에서 남은 미세 역할 조각은 같은 Near/Far 구역의 가장 긴 경계를 공유하는 이웃에 재배분한다. 이때 선택 대지·정확 Near 경계·XY는 움직이지 않는다.

도로는 같은 연속지적도의 도로 지목 필지로 정했다. 도로 중심선과 폭 추정은 제거했다. 주변 투영선은 없애고 XY로 남겼으며, 설계 대상의 대지경계만 필요한 모드에서 지형에 투영한다. XY 전용 생성은 DEM·입체 계산 없이 같은 평면·정보·생성 경로를 사용한다.

**결과.** 모델의 편집 편의와 취득 자료의 보존을 따로 검증할 수 있게 됐다. 도로 필지와 모델의 정합성은 얻었지만 실제 차도·보도·광장·잔디를 구분하는 기능은 아니다. 건물과 필지의 원천 불일치도 건물을 이동·축소해 숨기지 않는다.

Near 범위는 대지의 면적 중심에서 가장 먼 외곽까지의 거리 R에 배수를 곱한 원이다. 겹치는 원 묶음은 공통 외접선과 원호로 감싸고, 떨어진 묶음은 독립적으로 유지한다. 연속 Near 지형은 DEM 셀의 네 높이 표본을 두 축 방향으로 선형 보간한 쌍선형 높이장을 U/V 차수 1의 NURBS로 표현한다. 셀 사이 위치는 이어지지만 기울기까지 연속인 C1 곡면은 보장하지 않는다. Far의 기본 Mesh와 필요한 영역의 NURBS를 구분해, 전체를 NURBS로 만드는 저장·편집 비용을 피했다. 곡면을 더 부드럽게 만드는 것과 원천 높이 정보가 더 정확해지는 것은 별개다.

## 2. 건물 지반 통계와 취득 범위

**문제와 영향.** 건물 중심점 하나의 높이로 배치하면 긴 건물이나 경사지 건물의 일부가 뜬다. 전체 지반을 확보하려고 조회 범위를 넓힐 때 새 건물까지 생성 대상에 넣으면, 그 건물 때문에 다시 범위를 넓혀야 하는 연쇄가 생긴다.

**검증.** 평지·경사·중정·다중 외곽에서 전체 윤곽의 최저점과 면적 가중평균을 해석 가능한 기대값과 비교했다. 범위 경계의 건물에는 전체 지반을 확보하되, 추가 취득 범위의 다른 건물이 생성 대상으로 늘어나지 않는지 확인했다. 도로 전체 교차와 공간 후보만 조회한 통계도 대조했다.

**원인.** 건물의 배치 기준과 자료 취득 기준이 모두 출력 사각형에 묶여 있었다. 통계 계산에서도 건물 윤곽을 셀마다 다시 고정 격자로 잘라 교차점을 반올림하면, 조각의 합산 면적이 원래 윤곽과 달라졌다.

**변경.** 생성 대상은 최초 출력 범위에서 한 번 확정한다. 이후 그 건물들의 전체 지반에 필요한 필지·DEM만 추가 취득하고, 넓어진 범위로 건물을 다시 수집하지 않는다. 통계용 교차는 강건한 평면 연산으로 계산하고 쌍선형 높이를 적분한다. 원래 전체 윤곽의 면적 검증을 유지하며, 누락을 숨기도록 잘린 면적으로 결과만 재정규화하지 않는다.

건물 지붕은 계단화·굴착 전 보정 지형의 면적 가중평균에 건물 높이 H를 더해 정한다. H는 사용할 수 있는 원천 높이, 지상층수×층당 높이, 기본 높이 순이며 현재 공급원에서는 뒤의 두 경로를 사용한다. 일반 기초는 건물 아래 전체 출력 지반의 최저점보다 1m 낮춘다. Far도 중심점 배치를 제거하고 같은 전체 통계를 사용한다.

**결과.** 범위 확대가 생성 대상 확대를 부르는 순환을 없앴다. 건물 아래 낮은 골까지 고려하므로 경계선 높이만 읽을 때의 떠 있는 부분도 방지한다. 급경사에서 지형이 지붕보다 높아 건물 일부가 묻히는 경우는 지붕을 임의로 올리지 않는다. 기초는 지형에 꽂히는 모델 표현이며 구조 기초·지하층 설계가 아니다.

## 3. Contour 판·기초·대지 본체

**문제와 영향.** 연속 곡면을 건물마다 파는 방식은 상면 절단, 굴착 벽, 바닥과 표시용 삼각형의 경계를 모두 맞춰야 했다. 바닥을 더 내려도 평면 경계의 잘못된 대응은 해결되지 않았다. 등고판 표현에는 일정한 단면과 높이 구간이 더 직접적인 자료구조였다.

**검증.** 평지·경사·안장 지형, 중정·분리 영역·접촉 단면에서 판의 일정 단면·양의 두께·닫힘(폐합)·체적을 검사했다. 도로 내림 0·간격 미만·동일·초과, 건물 겹침, 대지 접촉, m/mm를 포함했다. 실제 객체가 Extrusion인지도 확인했으며 형식이 안 맞는 결과를 Brep로 대체해 통과시키지 않았다.

**원인.** 평면에서 결정한 굴착 경계와 실제 NURBS 상면의 분할·벽 연결이 별도로 복원됐다. 완성된 곡면 입체의 부분 굴착을 등고판에도 적용하면 일정 단면이 아닌 홈이 생겨 Extrusion의 이점을 잃는다.

**변경.** 독립 곡면 굴착을 제거하고 선택적 Contour의 평면 차집합에 굴착을 통합했다. 높이 간격 Δ마다 해당 레벨 이상인 영역을 구한 뒤 도로·대지·기초 구멍을 처리한다. 한 판은 외곽·구멍과 하단·상단 높이로 정의한다. 작은 돌출은 입체 합치기로 남기지 않고 생략해 아래 판이 드러나게 한다.

건물 전체가 Near 안에 있고 그 경계에 닿지 않을 때만 Near 건물이다. 선택 대지와 접촉·교차하는 건물은 굴착하지 않는다. 굴착 대상의 바닥은 건물 아래 노출판 바닥 중 가장 낮은 레벨이며, 평지에서도 적어도 한 판을 판다. 도로 상판이 내림으로 얇아졌다면 그 판의 바닥까지만 판다. 양의 면적으로 겹친 건물 묶음은 가장 낮은 기초 바닥을 공유하고 지붕은 각각 유지한다.

선택 대지는 계단화하지 않고 별도의 곡면 NURBS 입체로 만든다. 최저 상세 레벨을 L, 깊이를 D라 하면 지지판은 `[L−Δ,L]`, `[L−2Δ,L−Δ]`, 기단은 `[L−D,L−2Δ]`다. 대지 본체는 기단 윗면까지 내려온다. 도로 분리 시 노출된 도로 상판만 내림값만큼 얇게 하고, 아래 판 전체를 이동시키지 않는다.

Near/Far 접속은 각 판을 따라 연결 Mesh를 만드는 대신, 계단화 전 보정 지형의 정확 Near 경계에서 기단 윗면까지 캡(상·하단 막음면) 없는 수직 NURBS 외벽을 내린다. Far 쪽 도로 높이와 단차를 상단에 적용한다. 판 옆면과의 겹침을 허용하므로 노출판별 경계 절단과 높이차 부호 탐색이 필요 없어졌다.

**결과.** Contour는 평면 계산과 높이 구간, 선택 대지는 연속 곡면이라는 책임으로 나뉘었다. Near 건물 본체·기초와 등고판은 Extrusion으로 직접 생성한다. Far 건물은 선택한 형식을 유지한다. Contour OFF에서는 곡면을 파지 않고 건물과 지형을 겹친다. 이 전환은 모델 표현과 굴착 정책의 변경이다.

파라펫도 같은 원칙을 사용한다. 지붕 영역 P를 폭 w만큼 안쪽으로 줄인 영역을 빼서 `P − inset(P,w)`를 별도 Extrusion으로 만든다. 중정과 좁은 지붕의 띠를 먼저 합친 뒤 프로파일을 나눠, 분해 이음선에 파라펫이 생기지 않게 했다. 10×8m 지붕, 폭·높이 0.3m의 독립 기대값은 단면 10.44㎡, 체적 3.132㎥다. 본체·기초·파라펫은 확정 윤곽을 공유하며 지반이나 Contour를 다시 계산하지 않는다.

## 4. 평면 경계와 수치 안정성

**문제와 영향.** 큰 모델에서만 실패하는 것처럼 보인 경계 오류 중에는 유한 선분을 무한 지지선으로 잘못 연결한 문제와 작은 NURBS 구간의 적분 문제가 있었다. 허용오차를 키우면 증상을 줄일 수 있어도 원래 대지·원호와 다른 형상을 만들 위험이 있다.

**검증.** 종로·군포·감천 등의 실패 입력을 줄여 유한 직선·원호, 접선·공유 끝점, 구멍 소유권과 퇴화 프로파일을 검사했다. 한 공유 끝점의 거리는 허용값 2×10⁻⁶m에 대해 2.00000000916134×10⁻⁶m로 계산됐다. 초과분은 약 9.16×10⁻¹⁵m였지만 기존 분기가 연결을 거절했다.

현재 구현의 수치 계산은 다음 합성 입력으로 다시 측정했다.

| 현재 확인 | 입력과 기대값 | 관측 결과 |
|---|---|---|
| 작은 NURBS 구간의 면적 | 100×40m 사각형 위에 최대 높이 6m의 포물선 아치. 직선에 길이 4×10⁻⁷m 구간 포함. 면적 `4,000 + (2/3)×100×6 = 4,400㎡` | m/mm × 2위치(원점, x+100km·y−100km) × 정·역방향의 8조건. 최대 절대 오차 **9.095×10⁻¹²㎡** |
| 같은 원 위 점 판정 | 1m 정사각형의 세 꼭짓점이 만드는 원에 대해 나머지 점을 원 위·표현 가능한 한 단계 안·밖에 배치 | 원점과 x·y 모두 +100km 이동한 위치에서 각각 3조건, 총 6조건 모두 기대 분류와 일치 |

두 번째 입력의 한 단계는 원점에서 약 1.11×10⁻¹⁶~2.22×10⁻¹⁶m, 이동 후 약 1.46×10⁻¹¹m였다. 이는 입력한 double 값의 안팎 분류를 검증한 것이다.

**원인.** 가까운 긴 지지선을 사후 선택하면 원래 유한 선분과 다른 교점을 얻을 수 있다. 원시 경계는 방향을 포함한 감김 횟수의 합이 0이 아닌 곳을 내부로 보는 NonZero 규칙으로 해석해야 했다. 이를 다음 단계에서 이미 정상인 외곽·구멍 목록으로 취급하면 소유권이 바뀌었다. NURBS 전체 매개변수 구간의 직접 적분은 극히 짧은 구간이 섞일 때 수치 조건이 나빠졌고, 같은 원 위 점의 부동소수점 판정은 삼각분할 대각선 교환을 반복시킬 수 있었다.

**변경.** 직선·원호의 유한 교점을 한 번 구하고 원본 식별자·매개변수 구간·공유 교점으로 폐곡선을 구성한다. 알려진 공유 끝점은 같은 노드를 사용한다. 격자 좌표의 허용 범위는 정수 거리 제곱으로 판정하며, 같은 격자 칸에 있다는 이유만으로 서로 다른 교점을 합치지 않는다.

방향과 감김 수로 내부를 정하는 원시 NonZero 목록은 진입점에서 교차를 분할하고 외곽·구멍 소유권을 확정한다. 반복 평면 연산은 같은 정밀도의 Polygon/MultiPolygon을 유지한다. NURBS 면적은 정확한 Bézier 구간을 국소 좌표와 정규화된 매개변수로 적분한다. 원 안팎 판정이 모호하면 원래 double 값을 정확한 이진 유리수로 취급해 부호를 결정한다.

연속 Near의 상면·외벽도 공간적 Join으로 연결을 다시 추측하지 않고 원본 변의 분할과 이미 알려진 변 쌍을 전달한다. 매우 짧은 직선·원호는 실제 경계를 지우지 않고 지원되는 NURBS 표현으로 묶는다.

**결과.** 허용오차 확대나 지역별 예외 대신 경계의 출처와 계산식을 고쳤다. 작은 구간의 면적·방향, 접점 분류와 실제 입체 연결을 각각 검사할 수 있게 됐다. 위 면적 오차는 분석식이 있는 합성 곡선의 계산 오차이며 실제 DEM의 정확도와 무관하다.

## 5. 공유 위상 기반 단면 추출

**문제와 영향.** 등고판의 평면을 구할 때 매 레벨마다 모든 삼각형을 자르고 다각형 합집합을 수행했다. 같은 변의 교점도 이웃 삼각형에서 따로 계산했다. 산지처럼 레벨이 많은 입력에서 단면 시간과 임시 할당이 커졌다.

**검증.** 당시 두 단면 추출 방식에 같은 보정 높이장을 입력하고, 준비 실행 1회 뒤 각각 5회 측정했다. 두 단면 중 한쪽에만 속하는 영역인 대칭차의 면적도 확인했다. 전체 경로 열은 같은 지역의 두 실험 빌드를 별도로 실행한 시간이다. 아래는 당시 원시 측정의 재집계이며 현재 제품 전체의 직접적인 변경 전후 측정은 아니다.

| 당시 입력·규모 | 반복 절단 단면 시간, 초 | 공유 단면 시간, 초 | 단면 누적 관리 할당, GB | 전체 경로 중앙값, 초 |
|---|---:|---:|---:|---:|
| 정릉 · 53레벨·110판/2,928객체 | 12.265 [12.238–12.470] | 0.125 [0.122–0.135] | 18.231 → 0.220 | 23.056 → 8.749 |
| 성수 접촉 · 6레벨·281판/3,987객체 | 3.220 [3.194–3.293] | 0.043 [0.041–0.050] | 4.775 → 0.064 | 48.773 → 17.166 |
| 감천 · 13레벨·24판/9,779객체 | 0.256 [0.255–0.260] | 0.006 [0.005–0.006] | 0.436 → 0.011 | 2.519 → 2.476 |

시간은 중앙값 [최솟값–최댓값], 할당은 중앙값이다. 단면 시간·할당에는 위상 구성 등 추출 준비와 레벨별 추출을 포함한다. 판·객체 수는 두 빌드에서 같았지만 출력 형상의 동등성을 뜻하지 않는다. 정릉의 레벨별 최대 대칭차는 약 6.006×10⁻⁵㎡였고, 비교한 최대 영역 면적은 32,858.708㎡였다. 미세 교점 차이가 있으므로 정확히 동일한 단면이라고 표현하지 않는다.

**원인.** 이미 있는 이웃 관계를 버린 채 각 삼각형을 독립 다각형으로 만든 뒤 합집합으로 다시 연결했다. 이웃 셀의 세분 수가 다르면 공유 변에 서로 다른 점이 생겼고, 양자화된 짧은 선분을 먼저 버리면 폐곡선이 끊어졌다.

**변경.** 정점·변·삼각형의 공유 위상을 한 번 구축한다. 이웃 셀의 공유 변 분할점을 먼저 맞추고, 각 삼각형이 지나는 높이 구간에만 활성화한다. 교점은 공유 변·레벨마다 한 번 계산한다. 반대 방향의 내부 경계를 소거한 뒤 남은 경계를 공통 격자에서 교차 분할·연결하는 노딩으로 외곽·구멍을 만든다. `z ≥ kΔ`의 포함 규칙을 유지해 같은 높이의 정점·변·평탄부도 처리한다.

후속 도로·선택 대지 제외·굴착·작은 판 정리·Extrusion은 확정된 단면을 사용한다. Rhino Mesh를 절단하는 경로가 아니라 높이장의 삼각 근사와 공유 위상을 다루는 내부 계산이다. 연속 Near의 쌍선형 NURBS를 직접 절단하는 결과와는 표현 차이가 있다.

**결과.** 단면 추출의 시간과 누적 할당은 크게 줄었다. 감천에서는 단면이 빨라져도 전체 시간은 거의 같았다. 전체 경로에는 출력 등 다른 차이도 있어 그 개선 전부를 추출기에 귀속하지 않는다. 당시 후보의 실행 소스 전체를 현재 다시 복원한 측정은 아니며, 당시 동일 높이장 비교의 원시 결과가 뒷받침하는 범위로 한정한다. 현재 구현은 평지·경사·안장·음의 고도·불균일 세분·구멍·접촉의 해석적 면적과 폐합 검사로 보호한다.

## 6. 백그라운드 준비와 명시적 생성

**문제와 영향.** 긴 형상 계산과 객체 추가를 함께 UI 스레드에서 실행하면 Rhino 편집이 막힌다. 작업을 패널에 묶으면 패널을 닫거나 다른 클라이언트로 옮겼을 때 준비 결과를 이어서 쓰기 어렵다.

**검증.** 준비 전후 객체·레이어·선택·정보가 바뀌지 않는지, 계산 중 사용자 편집과 문서 전환이 가능한지 검사했다. 명시적 생성, 중복 요청, 한 번의 Undo, 저장·재열기, 닫힌 문서와 늦은 결과의 해제를 서비스 검사에 포함했다. 패널과 외부 AI의 도구 호출 연결인 MCP가 시작한 작업을 서로 조회·생성하는 경로도 같은 작업 상태를 사용한다.

**원인.** 계산 결과의 소유권과 Rhino 문서 반영이 분리되지 않았다. HTTP 서버·패널·문서는 서로 다른 수명을 가지는데 연결 종료를 작업 취소와 동일하게 취급할 여지도 있었다.

**변경.** UI 스레드에서 문서 식별자·단위·허용오차와 입력을 복사한다. 독립 형상을 백그라운드에서 준비하고 `ready`로 보관한 뒤, 명시적 생성 요청에서만 객체·레이어를 추가한다. 상태는 `running → ready → creating → completed`이며 실패·취소는 별도로 처리한다.

준비 결과는 문서별 작업이 하나씩 소유한다. 패널 닫기·탭 전환·MCP 중지로 취소하지 않는다. 생성·폐기·문서 종료·실패 시 형상을 해제한다. 일반 편집은 준비를 무효화하지 않으며 생성 전에 원래 문서의 생존·단위·허용오차를 확인한다. 생성만 변경 잠금을 사용하고 반영 또는 복구를 끝낸다. 전체 모델과 XY가 같은 수명·반영 경로를 쓴다.

Topo 준비의 10분 자동 취소는 제거했다. 일반 조회와 개별 HTTP 응답 제한은 구분해 유지한다. 취소된 뒤 늦게 반환된 형상도 폐기한다.

**결과.** 계산이 끝난 뒤 사용자가 생성 시점을 선택하고 그동안 Rhino 작업을 이어갈 수 있다. 이는 응답성과 작업 분리의 개선이며 총 연산시간 단축을 뜻하지 않는다. 생성 단계에는 준비한 객체의 등록·Undo·화면 갱신이 남는다. Headless 문서 등록 시간으로 첫 화면 표시 속도를 대신 설명하지 않는다.

지도 역시 수명을 분리했다. macOS WebView의 Reload는 내장 HTML 대신 빈 페이지를 열 수 있었고, 페이지 초기화와 타일 요청이 같은 세대 번호를 쓰면 이전 메시지가 새 `ready`를 무효화했다. 브라우저 Reload를 차단하고 호스트의 KEY 변경 재로드만 허용한다. 페이지 ID와 타일 요청 순번을 분리해 이전 페이지 메시지를 먼저 거절한다. 작업 잠금 중에도 현재 페이지의 초기화는 받되 선택 변경은 막는다. 실제 WebView와 고정 메시지 순서 검사가 이 경로를 보호한다.

## 7. 검사의 의미적 동등성과 실제 입체 검증

**문제와 영향.** 당시 10개 지역×5개 설정의 50사례에서 44개 모델이 생성되고 6개가 준비에 실패했다. 임시 저장 검사는 생성된 44개 전부를 불일치로 보고했다. 검사 결함과 실제 기하 결함을 구분하지 않으면 정상 저장을 고치거나 잘못된 입체를 놓치게 된다.

**검증.** 저장 불일치 45,520개 객체는 재열기 후 숫자 LayerIndex가 바뀐 객체 집합과 일치했다. 레이어의 고유 식별자 GUID·부모·계층은 유지됐다. 대표 5조건은 새 스냅샷으로 생성 직후·저장 직후·재열기를 비교했다. 서로 다른 형상 reader/API를 사용한 보조 검사에서는 4,953개 객체의 범위 상자(bbox)에 차이가 나왔지만, 같은 Rhino API로 측정한 최대 차이는 약 2.84×10⁻¹⁴m였다.

별도의 저장 모델 검사에서는 113,987개 객체와 41,336개 닫혀야 하는 입체를 확인했다. 알려진 군포의 불량 입체 한 개를 검출했으며 추가 결함은 검출하지 못했다. 모든 형상 오류가 없다는 증명은 아니다. 처음 44조건 대부분에는 저장 전 원본 스냅샷이 없으므로 전부의 실시간 저장 동등성을 소급 확정하지도 않는다.

현재 저장 검사 대조군은 다시 실행했다. 레이어 번호만 달라진 양성 대조는 통과하고, 실제 레이어 배정 변경·객체 정보(Info) 변경·형상 이동·객체 누락의 네 음성 대조는 모두 차이를 검출했다.

**원인.** LayerIndex는 해당 문서의 표에서 레이어를 찾는 번호이지 문서 사이의 영구 식별자가 아니다. 서로 다른 측정 API의 bbox도 동일 기준이 아니었다. 반면 군포의 실제 결함은 양의 면적 약 0.000106㎡를 가진 프로파일이 경계 복원에서 두 점을 왕복하는 면적 0 경계로 변한 문제였다. 이 Extrusion은 자체 `IsValid/IsSolid`가 참이어도 Brep로 확인한 실제 형상은 닫히지 않았다.

**변경.** 저장 동등성은 각 문서에서 해석한 레이어 GUID·부모·표시 상태, 객체 GUID·형식·정보와 같은 API의 실제 형상을 비교한다. 형상 체크섬인 CRC는 보조 증거로만 쓴다. 옵션 차이도 무조건 불일치로 처리하지 않고 도로 점유·내림에 따른 전체 지반 평균과 기초 기준으로 설명한다.

입체는 준비 단계에서 프로파일 연결·양의 면적·외곽/구멍 관계를 확인하고, Extrusion의 검증용 Brep로 폐합·다양체성(분기 없는 표면 연결)·변 연결·양의 체적과 기대 체적을 검사한다. 건물·기초·파라펫의 중복 native 체적 계산은 공통 검사 한 번으로 합쳤다. 생성 단계에서 전체 기하 검증을 반복하지 않는다.

**결과.** 검사 오류 때문에 제품의 저장·레이어 정렬을 바꾸지 않았다. 실제 퇴화 형상은 유한 경계 구성부터 고치고 검증을 보강했다. 마지막 검증은 개발 테스트의 대체가 아니라 잘못된 입체가 Rhino 문서에 들어가는 것을 막는 방어선이다. 정상 입력이 검증에서 실패한다면 계산을 수정해야 하며 사용자 책임의 제약으로 돌릴 수 없다.

Rhino가 Extrusion을 화면에 그리는 Render Mesh와 실제 입체의 폐합은 별개다. 자체 형상과 직접 만든 Mesh는 Topo가 검증한다. Rhino가 등록 시 보존하지 않는 Extrusion의 사전 Render Mesh 준비는 제거했고, 표시 설정을 바꾸거나 잘못된 형상을 화면 문제로 분류하지 않았다. 열린 연결 외벽과 겹침 도로 면은 본래 열린 형상 계약으로 검사한다.

## 8. 반복 상세 정리와 기초 갱신

**문제와 영향.** Contour에서 같은 경계를 반복 정리할수록 미세 생략이 누적됐다. 건물의 자기 굴착 잔여부를 낮은 지반으로 읽으면 기초가 다시 내려가고 전체 판을 재계산했다. 비동기로 화면은 반응해도 준비가 지나치게 오래 걸리는 원인이었다.

**검증.** 회전 사각형, 실제 좁은 띠, 회전 건물의 평지 굴착을 현재 제품 계산으로 다시 측정했다.

**원인.** 도로 경계와 정리된 경계를 각각 모델 격자로 반올림한 뒤 차집합하면, 실제로 생략하지 않은 가늘고 긴 영역이 생겼다. 이를 위 판에 누적하고 노출면을 표본화·재격자화해 지반을 조회하면서 출력과 조회의 원본이 달라졌다. 기초 변경마다 전체 판·누적 합집합·노출면을 다시 만드는 비용이 겹쳤다.

**변경.** 원단면과 역할 분할을 불변 입력으로 유지한다. 생략 영역은 offset 중간 정밀도에서 먼저 확정한 뒤 한 번만 모델 격자로 전달한다. 이미 확정된 영역을 원시 선 목록으로 되돌려 정규화하지 않는다. 실제 판 출력과 지반 판정은 같은 유한 경계 영역을 사용한다. 범위 상자와 표본은 후보 검색에만 사용하고, 실제 면적 교차와 점·선 접촉을 구분한다.

생략 영역은 역할·레벨·범위로 조회하고, 노출면은 실제로 높이와 범위가 만나는 판만 의존 대상으로 둔다. 기초 바닥이 바뀌면 활성 구멍이 달라지는 판, 생략이 전파되는 상위 판, 그 노출면과 관련 건물 묶음만 갱신한다. 누적 상태가 같아지면 전파를 멈추고 실제 변화가 없어질 때 수렴한다. 실제 좁은 지반이 사라져 필요한 하강은 유지한다.

대지 제외로 먼저 생긴 좁은 연결부도 역할 분할 직후 판정한다. 이 초기 생략은 큰 도로 내림이나 기초 하강으로 원단면 아래에 생긴 상세판까지 전달하되 지지판·기단의 피복은 별도로 유지한다. 30mm 연결부의 정확 단면 생략, 상하 지지와 보호 경계를 검사한다.

**결과.** 표의 준비 시간은 줄었지만 판 수와 생략 면적도 바뀌었다. 따라서 동일 형상 최적화로 분류하지 않는다. 불필요한 경계 손실을 고친 결과와 계산 재사용 효과가 함께 포함된다.

이전 자동 기한 안에 완료되지 않았던 불광 입력은 수정 후 기초 분리 33.287 [33.060–33.460]초, 합침 32.391 [32.150–33.150]초에 준비됐다. 각각 5회이며 1,169판과 생략 합집합 약 5.577721㎡가 일치했다. 완료된 이전 시간은 없으므로 가속 배수는 계산하지 않는다. 반복 횟수를 고정하거나 면적 문턱을 높여 잔여부를 무시한 결과도 아니다.

## 9. 셀 검색·계산 범위와 64타일 안정화

**문제와 영향.** 지형이 단순한 평지여도 타일이 늘면 준비 시간이 급격히 증가했다. 셀마다 전체 출력 영역을 검색하고, 작은 선택 대지와 각 패치에서 전체 취득 범위의 자료를 다시 구성하는 비용이 있었다. 타일 개수만으로 형상 계산 비용을 설명하기 어려웠다.

**검증.** 동일한 DEM 요청 레벨 15·원래 표본 해상도의 합성 높이장을 사용했다. 평지·Near OFF, 경사·도로/건물·Contour OFF, 굴곡 지형·Contour ON, 교차 도로·밀집 건물·중정·Contour ON의 네 장면을 비교했다. 검색 제거 전후 32·64타일의 8조건에서 실제 형상·역할·정보·XY·대지경계 동등성을 확인했다.

선택 대지는 80×60m로 고정했다. Near ON은 2R, Contour ON은 간격 1m·깊이 30m를 사용했다. 도로 분리/200mm 내림·기초 합침·Far Mesh·Near 파라펫 폭/높이 300mm 조건이며, 평지 장면에는 Near·도로·건물이 없다. 따라서 밀집 장면도 출력 범위 전체를 계단화한 실험은 아니다. 64타일의 높이 표본은 259,081개였다.

합성 높이는 평지 `z=100`, 경사 `z=100+0.006x+0.004y`, 굴곡 두 장면 `z=100+12sin(x/180)cos(y/210)+0.002x`다. x·y는 지역 원점의 수평 거리, z는 높이이며 단위는 m다. 도로 폭/간격은 10/120m, 건물은 14×12m이며 밀집 장면은 40m 간격과 일부 6×4m 중정을 사용했다.

셀 검색 비교는 장면별 준비 실행 1회 뒤 5회 측정했다. 아래 범위는 관측 최솟값–최댓값이다.

| 당시 합성 조건 | 전체 준비 변경 전, 초 | 전체 준비 변경 후, 초 | 중앙값 감소 |
|---|---:|---:|---:|
| 32타일 평지 · Near OFF | 37.071 [34.658–38.162] | 10.133 [10.051–10.717] | 72.7% |

**원인.** 셀 수 C마다 영역 R개를 검색해 `O(C×R)`의 후보 검사가 발생했다. 64타일 평지의 대표 지형 호출에서는 셀·영역이 각각 258,064개여서 66,597,028,096회 검색이 필요했다. 이는 후보 방문 수이며 CPU 명령 수나 작업 전체 호출 수가 아니다.

**변경.** 기존 셀별 목록을 한 번 채우고 셀에서 직접 조회한다. 분류는 `O(R)`이며 삼각분할과 대지경계의 도로 단차 투영이 같은 목록을 사용한다. 원래 영역·순서·역할을 보존하고 셀별 임시 배열·목록 복사를 제거했다. 정확 Near는 근사 목록 유무가 아니라 정확 분할의 셀 키로 계속 출력한다.

후속 안정화에서는 작은 선택 대지에 필요한 원래 지형 셀 창만 사용하고, 패치마다 만들던 도로 색인을 작업 안에서 공유했다. 도로 보정은 영향 없는 노드의 해가 0인 성질을 이용해 영향 영역만 원래 순서로 반복한다. 목적함수·잔차·±3m 제약을 바꾸지 않았다. 떨어진 Near 사이 Far 표고가 등고 범위를 불필요하게 늘리지 않도록 독립 Near별 셀 창을 사용하되 공유 세분과 경계 복원에 필요한 이웃을 유지한다.

**결과 — 검색 제거.** 대표 호출의 후보 방문이 66,597,028,096회에서 영역 분류 258,064회로 줄었다. 같은 64타일 평지의 누적 관리 할당은 46.289 → 46.159GB로 거의 같았고, 프로세스 최대 메모리 중앙값은 2.603 → 2.726GB였다. 검색 시간 감소를 같은 비율의 메모리 감소로 해석할 수 없다. 기하 계산·삼각분할 자체를 바꾼 최적화도 아니다.

**결과 — 후속 계산 범위와 재사용.** 별도 변경 전후 비교에서도 준비 실행 1회·측정 5회와 32·64타일 네 장면의 8쌍 기하 동등성을 확인했다.

### 자원 한도 실험의 해석

DEM 한 타일의 원시 높이는 16,900바이트이며 64개는 약 1.08MB다. 이것만으로 전체 비용을 설명할 수 없다. 높이장·평면 분할·도로 보정·삼각형·판·Rhino 형상이 추가되며, 같은 타일 수에서도 Near 크기·등고 간격·경계 복잡도에 따라 비용이 달라진다.

격리된 실험 빌드에서 96·128타일도 확인했다. 96타일은 389,385개, 128타일은 519,689개 높이 표본을 사용했다. 96타일 네 장면과 128타일 평지는 완료됐다. 96타일 평지와 밀집의 반복 측정 중앙값은 각각 52.488 [51.769–60.459]초, 146.670 [145.169–147.594]초였다. 128타일 평지는 94.882 [92.479–95.755]초였다. 세 조건 모두 준비 실행 1회 뒤 5회 측정했다.

128타일의 복잡한 세 장면은 당시 빈 Rhino 대비 추가 메모리 2GiB의 실험 중단선으로 중단했다. 이는 제품의 기하 실패나 128타일이 원천적으로 불가능하다는 증거가 아니다. Near 크기가 고정된 실험이므로 모든 Contour 복잡도에 대한 안전성도 설명하지 못한다.

제품의 DEM 취득 한도는 64타일, 높이 표본은 100만 개로 유지했다. 공급원 규정이 아니라 요청량 보호값이다. 설정으로 알 수 있는 양은 준비 전에, 건물 전체 지반 때문에 늘어난 양은 DEM 요청 전에 다시 확인한다. 정상 수집·수렴·정제를 임의 요청 횟수·고정 반복 횟수·출력 개수만으로 실패시키던 내부 제한은 제거하고 실제 원천 완전성·수치 표현·형상 검증은 유지했다.

후속 64타일 검증의 동등성·반복 측정·준비 결과 보유·넓은 Near를 포함한 45회 진단은 모두 통과했다. 이 비교의 양쪽 구현에는 같은 추가 메모리 4GiB 감시선을 적용했다. 앞선 2GiB 실험과 완료율을 직접 비교하지 않는다. 전체 일반 12묶음과 Rhino 8묶음도 통과했으며 측정 소스와 현행 구현의 일치, 빌드·Yak·설치 파일의 모듈 해시와 실제 로드된 모듈을 대조했다. 확인한 장면에서의 완료 근거이며 모든 지역·설정이나 Windows에 대한 보장은 아니다.

- 시간 표는 중앙값 [최솟값–최댓값]이다. 준비에는 입력 자료를 메모리에 읽은 뒤 계산·Rhino 형상 준비·검증을 포함하며, API 통신이나 입력 파일 읽기 시간과 구분한다. 단면 시간은 추출 준비와 레벨별 추출의 합이다.
- 누적 관리 할당은 표에 명시한 계산 구간에서 새로 할당한 총량이다. 해제 후 다시 할당한 메모리도 더하므로 동시에 필요한 RAM이 아니다. 프로세스 최대 메모리는 입력 준비·형상 비교·등록을 포함한 실행 전체에서 표본으로 관찰한 working set이며 다른 native 자원·캐시도 포함한다. 준비 형상량은 형상 객체의 보고값으로 전체 보유 메모리와 같지 않다.
- GB·MB는 각각 10⁹·10⁶바이트, GiB는 2³⁰바이트다. CPU 시간·사용률 기록이 없는 측정에서 CPU 절감률은 추정하지 않았다. 특정 컴퓨터의 초 단위를 다른 환경의 처리시간 보장으로 사용하지 않는다.
- 정확성은 해석적 기대값, 폐합·체적·피복·정보·보호 경계와 변경 전후 실제 형상으로 확인했다. 객체 수·파일 크기가 같다는 사실만으로 기하 동등성을 판정하지 않았다. 표시 Mesh의 근사 기준과 원천 자료의 정확도도 구분한다.
- 과거 성능값은 보존된 원시 측정을 재집계한 것이다. 현재 추가 실측은 합성 최소 입력과 저장 대조군에 한정하며, 과거 전체 지역 실행을 새로 재현한 결과로 해석하지 않는다.
